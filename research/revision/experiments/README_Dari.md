# راهنمای مطالعهٔ کنترول‌شدهٔ بازنویسی فارسی و دری

این پوشه روش اجرای یک مقایسهٔ تازه را نگه می‌دارد. این مقایسه، اجرای تاریخی Llama یا بازتولید ارقام PDF قدیمی نیست. رسیدهای اجرا و تحلیل مستقل، ۸۰۰ پاسخ موفق در بخش اصلی و ۸۰ پاسخ در ماژول عددیِ جدا را تأیید می‌کنند. آرشیف اولیه ۴۰۰ پاسخ موفق مدل اصلی و ۴۰۰ خطای دسترسی nano دارد؛ آرشیف ثانوی ۴۰۰ پاسخ موفق GPT-4o mini را نگه می‌دارد.

## طرح ثبت‌شده

از ۷۰۲ ورودی بخش test، با seed برابر ۲۰۲۶، تعداد ۱۰۰ ورودی از ۱۰۰ گروه متفاوت انتخاب شده‌اند. انتخاب پیش از خواندن خروجی مدل ثبت شده است. همان ۱۰۰ ورودی در هر هشت ترکیب مدل و شرط استفاده می‌شود.

دو مدل با نام دقیق و ثابت عبارت‌اند از:

- `gpt-4.1-mini-2025-04-14`
- `gpt-4o-mini-2024-07-18`

| شرط | مثال واقعی داخل پرامپت | کاربرد |
|---|---:|---|
| LLM0 | ۰ | مدل با دستور، بدون مثال جایگزین |
| semantic1 | ۱ | نزدیک‌ترین مثال train |
| semantic4 | ۴ | چهار مثال نزدیک train |
| random4 | ۴ | چهار مثال تصادفی با انتخاب ثابت |

در مجموع، مقایسهٔ اصلی شامل ۸۰۰ پاسخ موفق مجزا است. ۴۰۰ خطای دسترسی nano در آرشیف اولیه نگهداری شده‌اند و کیفیت‌سنجی نشده‌اند. ماژول پوشش عددی نیز ۸۰ پاسخ جدا دارد. temperature و seed تولید هر دو صفر و سقف پاسخ ۲۵۶ توکن است. چهار درخواست می‌توانند هم‌زمان اجرا شوند. هر پاسخ باید نام دقیق مدل، پایان عادی `stop`، متن غیرخالی و مصرف توکن منطبق داشته باشد. پاسخ ناقص یا مدل جایگزین، نتیجهٔ موفق حساب نمی‌شود.

فقط ستون `ai` برای embedding استفاده شده است. مدل embedding، `sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2` با revision دقیق `e8f8c211226b894fcb81acc59f3b34ba3efd5f42` است. بازیابی با cosine روی بردارهای نارمل‌شده انجام می‌شود و مثال‌ها فقط از ۲۴۳۸ جفت train می‌آیند. مرجع‌های test داخل پرامپت یا embedding نمی‌روند. فاصلهٔ نامرتبط میان برچسب‌های سبک، به معنی نامرتبط‌بودن قطعی محتوا نیست؛ برچسب سبک برای فیلتر استفاده نشده است.

کلید API داخل پلان، پاسخ‌ها، اسکریپت یا بستهٔ مقاله نگهداری نمی‌شود. فایل خصوصی محیط اجرای اصلی، جزو بستهٔ تحویل نیست.

## فایل‌ها و منشأ شواهد

| مسیر | محتوا |
|---|---|
| `api_study_v1/plan.json` | انتخاب ورودی، متن کامل پرامپت، مثال‌ها، مدل‌ها و حدود اجرا |
| `api_study_v1/plan.sha256` | هش پلان منجمد |
| `api_study_v1/attempts.jsonl` | ثبت هر تلاش HTTP پیش از ارسال |
| `api_study_v1/responses/*.raw.json` | پاسخ خام سرویس برای درخواست موفق یا پاسخ قابل بررسی |
| `api_study_v1/responses/*.json` | نتیجهٔ پردازش‌شده، شناسهٔ درخواست، هش، وضعیت و مصرف |
| `api_study_v1/completion.json` | رسید تکمیل یا تکمیل همراه با خطا |
| `embeddings/metadata.json` | هویت embedding، revision، هش متن‌های ورودی و نسخهٔ کتابخانه‌ها |
| `tests/` | آزمایش‌های آفلاین حفاظت روش؛ متن‌های ساختگی آن‌ها نتیجهٔ علمی نیستند |

نام ستون `human` به‌تنهایی انسانی‌بودن، حفظ معنا یا درستی مرجع را ثابت نمی‌کند. معیارهای خروجی باید از ارزیابی طبیعی‌بودن و بررسی معنایی جدا گزارش شوند. دو مدل این مطالعه از یک ارائه‌کننده‌اند؛ نتیجه به همهٔ مدل‌ها یا همهٔ گونه‌های دری تعمیم داده نمی‌شود.

## بررسی بدون کلید و بدون هزینه

ساختار بسته را نگه دارید: پوشهٔ `persian_humanization_revision` و پوشهٔ `Persian_Humanizer_Ai` باید کنار هم باشند. سپس از داخل پوشهٔ revision اجرا کنید:

```bash
python -m unittest discover -s experiments/tests -v
```

پلان اجرای اصلی، مسیرهای مطلق محیط مبنا را نیز ثبت کرده است. در همان محیط، فرمان زیر فقط بررسی و dry run انجام می‌دهد و هیچ درخواست مولدی نمی‌فرستد:

```bash
python experiments/api_experiment.py run --directory experiments/api_study_v1
```

اگر بسته به کمپیوتر دیگری انتقال یافته باشد، همان پلان را برای اجرای تازه تغییر ندهید؛ یک پلان تازه با فرمان بخش بعد بسازید و dry run را روی آن اجرا کنید. این کار نسخهٔ اصلی شواهد را حفظ می‌کند. آزمایش‌های پوشهٔ `tests` برای خواندن فایل‌های همراه، مسیر نسبی بسته را هم می‌شناسند؛ اجرای خود پلان منجمد مسیرهای اصلی را عمداً بازنویسی نمی‌کند.

برای بررسی corpus و آزمایش‌های توکن‌سازی، از مسیر revision اجرا کنید:

```bash
python -m unittest discover -s corpus_analysis -p "test_*.py" -v
python corpus_analysis/analyze.py --repo ../Persian_Humanizer_Ai --out /tmp/persian_corpus_recheck
```

در Windows برای `--out` یک مسیر نو در کمپیوتر خود، مانند `C:\temp\persian_corpus_recheck`، انتخاب کنید. برای حفظ شواهد، نتیجهٔ محاسبهٔ دوباره را روی پوشهٔ اصلی تحلیل ننویسید.

## بازاجرای تازه با API

Python 3.12 و NumPy برای ساخت پلان از بردارهای همراه کافی‌اند؛ کلاینت API از کتابخانهٔ استاندارد Python استفاده می‌کند. برای بازساختن embedding، وابستگی‌های Sentence Transformers نیز لازم‌اند. محیط و نسخه‌های اجرای اصلی در فایل میتادیتا ثبت شده‌اند؛ نصب نسخهٔ دیگر، بازاجرای همان محیط را ثابت نمی‌کند.

کلید خودتان را در یک فایل خصوصی **بیرون از پوشهٔ بسته** و با متغیر `OPENAI_API_KEY` قرار دهید. کلید را در گفتگو، GitHub یا فایل نتایج ننویسید. برای اجرای تازه، یک پوشهٔ تازه انتخاب کنید:

```bash
python experiments/api_secondary_experiment.py prepare --manifest corpus_analysis/split_manifest.json --vectors experiments/embeddings/vectors.npz --embedding-metadata experiments/embeddings/metadata.json --out experiments/api_study_reproduction --limit 100 --seed 2026 --budget 2.00
python experiments/api_secondary_experiment.py run --directory experiments/api_study_reproduction
```

پس از بررسی شمار ۸۰۰ درخواست و سقف هزینه، اجرای واقعی را با مسیر فایل خصوصی خود آغاز کنید. برای مثال، اگر فایل خصوصی یک پوشه بالاتر از ریشهٔ بسته باشد، مسیر متناسب همان محل را جایگزین کنید:

```bash
python experiments/api_secondary_experiment.py run --directory experiments/api_study_reproduction --env-file /absolute/path/to/private.env --execute --concurrency 4 --max-retries 0
```

در Windows نیز همین فرمان با مسیر مطلق فایل خصوصی Windows کار می‌کند. در بازاجرای تازه، سقف انتخاب‌شده ۲ دالر است و اسکریپت برآورد محافظه‌کارانه را پیش از اجرا بررسی می‌کند. این برآورد مصرف واقعی یا بل نهایی نیست. رسید اجرا، مصرف موفق ثبت‌شده را جدا حساب می‌کند؛ تخفیف احتمالی cache در برآورد محافظه‌کارانه منظور نشده است.

اسکریپت به‌طور پیش‌فرض تلاش دوباره ندارد. اگر خطا، پاسخ ناقص یا تلاش ناتمام ثبت شد، آن را حذف نکنید و به نام پاسخ موفق معرفی نکنید. برای بازیابی، باید یک اجرای جدا و مستند با رابطهٔ روشن به درخواست‌های ناقص ساخته شود. تغییر خاموش پلان، متن پرامپت یا مدل هنگام ادامهٔ اجرا مجاز نیست.

## جایگاه Ollama

فایل `harness.py` مسیر جداگانهٔ اجرای محلی Ollama را نگه می‌دارد. موجودبودن این اسکریپت یا نصب ابزار Ollama، به معنی اجرای Llama در مطالعهٔ API نیست. هیچ نتیجهٔ OpenAI به نام نتیجهٔ Llama گزارش نمی‌شود. برای اجرای Ollama، نام مدل و digest واقعی، embedding و پلان جدا لازم است.

## ارزیابی و حدود ادعا

خروجی با ورودی مقایسه می‌شود تا حفظ واژه، طول و تغییر عددها به‌صورت تشخیصی روشن شود. مقایسه با مرجع دیتاست، به‌عنوان توافق با یک مرجع تأییدنشده گزارش می‌شود. ROUGE کم یا زیاد، به‌تنهایی نمرهٔ طبیعی‌بودن یا صحت معنا نیست. تفاوت رقم‌ها نیز همیشه خطا نیست؛ تبدیل عدد نوشتاری به رقمی باید از ادعای تازه جدا شود.

تحلیل جفتی باید واحد مستقل را همان ۱۰۰ ورودی یا گروه بگیرد؛ هشت پاسخ یک ورودی، هشت سوال مستقل نیستند. نمره‌دهی انسانی فقط زمانی تکمیل‌شده محسوب می‌شود که اشخاص واقعاً خروجی‌ها را بررسی و نمره‌های خود را ثبت کرده باشند. فایل خالی، ارزیابی هوش مصنوعی یا آزمایش نرم‌افزار جای آن معرفی نمی‌شود.

## بررسی مستقل تمام پاسخ‌های ذخیره‌شده

از پوشهٔ اصلی بسته، `python verify_package.py` را اجرا کنید. این دستور به کلید API نیاز ندارد. برای فرمان‌های تفصیلیِ تحلیل با مسیر قابل انتقال، `ANALYSIS_README.md` را ببینید. تحلیل عددی با `analyze_numeric_results.py` انجام می‌شود؛ آرشیف آن در `api_numeric_diagnostic_run` است.
